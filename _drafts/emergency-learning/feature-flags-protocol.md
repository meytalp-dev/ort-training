# רֶצֶף — פרוטוקול Feature Flags (שליטת יכולות)

**גרסה:** 1.0 · **תאריך:** 15.7.2026 · **מזהה משימה:** W0-03 · **סטטוס:** 🟢 אפיון עבודה
**מסמכי-אב:** `prd.md` 3.0 §2 (שלושה מוצרים, תשתית אחת) · `security-minimization.md` · `worlds-detailed-spec.md`
**מימוש:** `feature-flags.js` (המנגנון) · `feature-flags.html` (הדגמה חיה) · **מיקום:** `_drafts/emergency-learning/`

> ⚠️ **אל תבלבלו עם `flags-protocol.md`.** אותו קובץ עוסק ב**דגלים הרגשיים** של ה-check-in (T2.3 — "קשה לי", "רוצה לדבר"). המסמך הזה עוסק ב**דגלי יכולת** (Feature Flags) — הדלקה/כיבוי של מוצרים ומודולים. שני מובנים שונים לגמרי של המילה "דגל". בגלל ההתנגשות, מנגנון היכולות מתועד כאן בקובץ נפרד ולא דורס את פרוטוקול הדגלים הרגשיים.

---

## 0. מה זה, בשורה אחת

תשתית אחת מפעילה שלושה מוצרים + יכולות-משנה. **Feature Flag** הוא מתג בוליאני שקובע אם יכולת קיימת עבור קהל נתון. הוא נשלט בשש רמות, והספציפי גובר. **כלל ברזל: מודול כבוי לא מופיע בניווט — לא מעומעם, לא נעול; פשוט לא קיים.**

זה מה שמגן על היכולת לספק: משרד העבודה יכול להדליק "חירום בלבד", חירום+העשרה, או את שלושתם — בלי שנבנה שלוש מערכות, שלושה מסדי נתונים או שלושה ממשקי תלמיד.

## 1. שמונת הדגלים

| דגל | מוצר | ברירת מחדל | תלוי ב- | מה הוא מדליק |
|-----|:----:|:----------:|:-------:|--------------|
| `emergencyLearning` | A · חירום | 🟢 **דלוק** | — | check-in, יחידות קצרות, מסלול הצלה, דופק, יומן קשר |
| `routineLearning` | B · שגרה | ⚪ כבוי | — | העלאת חומר, בניית יחידות, מורה מחליף, שליחת משימות בשגרה |
| `differentiation` | B · שגרה | ⚪ כבוי | `routineLearning` | 3 רמות תמיכה לאותה יחידה (תמיכה / ליבה / אתגר) |
| `enrichmentCourses` | C · העשרה | ⚪ כבוי | — | קטלוג קורסים על מנוע היחידות (עצמאי — לא דורש שגרה) |
| `aiAuthoring` | רוחבי | ⚪ כבוי | — | AI לצד המורה/יוצר התוכן, **על חומר לימוד בלבד** |
| `parentMessaging` | רוחבי | ⚪ כבוי | — | יידוע הורים רגוע (פונקציה, לא אפליקציה) |
| `certificates` | רוחבי | ⚪ כבוי | — | תעודת סיום קורס/מסלול |
| `nationalDashboard` | רוחבי | ⚪ כבוי | — | תמונה ארצית מצרפית בלבד (אין drill לתלמיד) |

**מדוע רק חירום דלוק כברירת מחדל:** MVP-A הוא המוצר שנמסר. כל השאר הוא **opt-in** — עיקרון המינימיזציה (`security-minimization.md` §1): יכולת שלא הודלקה = סיכון שלא צריך להגן עליו. `aiAuthoring`, `parentMessaging` ו-`nationalDashboard` כבויים כברירת מחדל **במכוון** כי כל אחד מהם מרחיב את היקף החשיפה (AI חיצוני / PII של הורים / ריכוז נתוני קטינים ארצי).

## 2. שש רמות השליטה — והקדימות

הדגלים נשלטים בשש רמות. **הסדר הוא הקדימות: כל רמה גוברת על הכללית ממנה. הספציפי מנצח.**

```
התקנה  →  ארגון  →  בית ספר  →  שכבה  →  משתמש  →  פיילוט
(כללי)                                              (גובר על הכל)
```

| # | רמה | מי מגדיר | דוגמה |
|---|-----|----------|-------|
| 1 | **התקנה** | ברירת המחדל של המערכת | חירום דלוק, השאר כבוי |
| 2 | **ארגון** | משרד העבודה / רשת | "כל בתי הספר ברשת — עם שגרה" |
| 3 | **בית ספר** | המנהל | "בבית ספרי — נדליק גם העשרה" |
| 4 | **שכבה** | מנהל / רכז | "שגרה רק לשכבת י'–י\"ב" |
| 5 | **משתמש** | חריג נקודתי | "למורה הזה — עוזר AI" |
| 6 | **פיילוט** | קבוצת ניסוי | "10 מורים בהתנסות — דיפרנציאליות" |

**מדוע פיילוט גובר על הכל:** פיילוט הוא override מכוון להרצת התנסות מבוקרת — הוא צריך להדליק (או לכבות) יכולת עבור קבוצת הניסוי **בלי תלות** בהגדרות בית הספר או המשתמש. לכן הוא הרמה האחרונה בשרשרת.

**ערך "ירושה":** רמה שלא מגדירה דגל = יורשת מהרמה הכללית ממנה. רק ערך מפורש (דלוק/כבוי) גובר. כך אפשר לכבות במפורש דגל ברמה ספציפית (למשל לכבות `parentMessaging` לבית ספר מסוים גם אם הארגון הדליק).

---

## 3. אכיפת תלויות

דגל שדורש דגל-אב שכבוי — **נכבה בכפייה**, בלי קשר למה שהוגדר בו. זה מונע מצב לא-עקבי.

- `differentiation` דורש `routineLearning`. אם שגרה כבויה — דיפרנציאליות כבויה, גם אם הדליקו אותה במפורש ברמת פיילוט. במטריצה זה מסומן **"תלות"** בעמודת הנגזרת.

התלות נאכפת **אחרי** חישוב כל שש הרמות — כך שאם שגרה נדלקת בשכבה ודיפרנציאליות בפיילוט, השילוב עקבי והדיפרנציאליות תישאר דלוקה.

---

## 4. כלל הברזל — ניווט

> **אין פריט ניווט למודול כבוי.**

זה לא קישוט — זו דרישת ליבה. פריט של יכולת כבויה **לא נכנס לרשימת הניווט** (`navFor()` מסננת במקור). לא מוצג מעומעם, לא נעול-עם-מנעול, לא מקושר למסך ריק. אם *כל* היכולות של פרסונה כבויות — **הפרסונה כולה מוסתרת** (`personaVisible()`).

### מיפוי פריט → יכולת (מתוך `feature-flags.js`)

| פרסונה | פריט ניווט | מותנה בדגל |
|--------|-----------|-----------|
| **תלמיד** | בית · התקדמות | תמיד (ליבה) |
| | משימות | חירום **או** שגרה |
| | קורסים | `enrichmentCourses` |
| | תעודות | `certificates` |
| **מורה + מחנך** | לוח בקרה · הכיתה שלי · שליחת משימה · ספרייה | חירום **או** שגרה |
| | דופק כיתתי | `emergencyLearning` |
| | יצירת תוכן | `routineLearning` |
| | עוזר AI | `aiAuthoring` |
| **מנהל** | דופק בית הספר · דוחות | חירום **או** שגרה |
| | מצב מערכת | תמיד (מתג המצב הוא ליבה) |
| | יידוע הורים | `parentMessaging` |
| **פיקוח ארצי** | תמונה ארצית · מפה | `nationalDashboard` (אחרת — הפרסונה כולה מוסתרת) |

> **הבחנה חשובה:** *מצב מערכת* (שגרה/מרחוק/חירום) הוא **מתג הפעלה, לא Feature Flag** — ראו `W0-04`. מתג המצב תמיד קיים אצל המנהל. הדגלים קובעים *אילו יכולות קיימות*; המצב קובע *איך הן מתנהגות*.

## 5. ה-API של המנגנון (`feature-flags.js`)

```js
RETZEF_FLAGS.resolve(context)      // → { flags:{...8}, source:{flag:level} }
RETZEF_FLAGS.isEnabled(flag, ctx)  // → boolean
RETZEF_FLAGS.navFor(persona, flags)      // → פריטי ניווט מותרים בלבד
RETZEF_FLAGS.personaVisible(persona, f)  // → האם הפרסונה מוצגת בכלל
```

`context` הוא אובייקט של רמות, כל רמה חלקית:

```js
const ctx = {
  organization: { routineLearning: true },
  school:       { enrichmentCourses: true },
  pilot:        { aiAuthoring: true }
};
const { flags, source } = RETZEF_FLAGS.resolve(ctx);
// flags.enrichmentCourses === true, source.enrichmentCourses === 'school'
```

`source` מחזיר לכל דגל את הרמה שהכריעה (או `'dependency'` אם נכבה בכפייה) — שימושי ל-Admin ולניפוי.

## 6. גבולות ומינימיזציה (חוסמים)

- **`aiAuthoring` לעולם לא מדליק AI פונה-לתלמיד.** הוא צד-מורה בלבד, על חומר לימוד. אין דגל שמדליק AI על נתוני תלמיד ב-MVP (`security-minimization.md` §3 שורה 1).
- **`parentMessaging` לא פותח גישת הורה** ל-check-in, ליומן הקשר או לתוכן רגשי — רק יידוע יוצא (§3 שורה 11).
- **`nationalDashboard` מצרפי בלבד** — האכיפה היא במודל הנתונים, לא בדגל. הדגל רק מציג/מסתיר; הוא לא "פותח" drill שאסור במבנה (§3 שורה 5).
- **ברירות המחדל שמרניות במכוון.** אין להדליק דגל רוחבי (AI/הורים/ארצי) כברירת מחדל של התקנה — רק opt-in מפורש ברמת ארגון/בית ספר ומעלה.

## 7. מה פתוח / דורש את מיטל

1. **קדימות פיילוט מעל משתמש** — האם פיילוט אכן צריך לגבור גם על חריג משתמש בודד? כרגע כן (הנחת עבודה). לאישור.
2. **התנגשות שם `flags-protocol.md`** — הוכרע בפועל: מנגנון היכולות תועד ב-`feature-flags-protocol.md` נפרד כדי לא לדרוס את פרוטוקול הדגלים הרגשיים. לאישור השם.
3. **מי מורשה לשנות דגל בכל רמה** — נשען על RBAC (`W0-02`). ברמת ארגון = משרד; בית ספר = מנהל; פיילוט = Admin/מנהל מערכת. לחיבור סופי כשמסך ה-Admin ייבנה (דחוי).
