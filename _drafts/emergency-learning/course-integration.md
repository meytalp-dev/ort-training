**מה זה:** בדיקה האם שני קורסים קיימים של Learni — **קורס AI לתלמידים** ו**פיננסקלאס** — יכולים להיכנס לתצוגה 7 (קורסי העשרה) של רֶצֶף **על מנוע היחידות הקיים**, במקום לבנות נגן קורסים כפול. המסמך מסכם: מה מתאים, מה חסר, ומה הדרך המומלצת. **אין כאן בנייה** — W7-04 נשאר דחוי עד שגל A וגל B יאושרו.

> **הכלל שמנחה את הבדיקה** (`prd.md` §2): *אין לבנות שלוש מערכות, שלושה מסדי נתונים או שלושה ממשקי תלמיד.* קורס העשרה = פרסונת-תלמיד מעל אותו **מנוע יחידות**, נשלט בדגל `enrichmentCourses`. לכן "שילוב" פירושו **ייבוא תוכן אל הסכימה הקיימת** — לא נגן שני.

## 1. נקודת ההשוואה — מנוע היחידות של רֶצֶף

`enrichment-course.html` כבר מגדיר קורס יחיד מקצה-לקצה (W7-01, בוצע) על סכימת יחידה אחת. כל שיעור הוא אובייקט:

```
LESSON = {
  id, icon, title, sub,
  lead,            // פתיח 1–2 משפטים "למה עכשיו"
  why,             // "למה זה חשוב" — רלוונטיות חיים/עבודה
  remember,        // הרעיון המרכזי המודגש
  portions: [ { idea, exLbl, ex, pin, alt } ],   // מנות קצרות: הסבר→דוגמה→מודגש
  questions: [ { txt, opts, answer, good, hint, rescue[] } ]  // תרגול + מסלול הצלה
}
```

מסביב: `CourseCard` (כותרת/יעדים/facts), רשימת שיעורים, `SequenceLine` למעקב, שמירת התקדמות ב-localStorage, תווית משך גמישה (`LearningDuration`, `prd.md` §5). **זהו פורמט היעד.** כל קורס שנרצה "לשלב" צריך להתמפות אליו.

## 3. חסמים ומגבלות (חוסמים לפני כל בנייה)

1. **🔴 מינימיזציה — הרכיב ה"חי" של קורס ה-AI.** רֶצֶף חוסם **AI פונה-לתלמיד ב-MVP** (`security-minimization.md`, `prd.md` §6, W8-03). יש להבחין:
   - תלמיד המשתמש בכלי AI חיצוני **בחשבון שלו** ללימוד = פעילות לימודית לגיטימית, לא הפרה.
   - רֶצֶף ששולח **תשובת/נתון תלמיד למודל חיצוני** = קו אדום, אסור.
   שילוב קורס ה-AI חייב לייבא רק את **התוכן הסטטי** (הסברים, מנות, שאלות). המסלול ה"חי" נשאר קישור/הנחיה חיצונית — **לא אינטגרציה של AI לתוך המנוע**.
2. **סקופ — דחוי נשאר דחוי** (`prd.md` §9). W7-04 אחרי גל A+B. קטלוג קורסים (W7-02) ותעודות (W7-03) גם דחויים — שילוב תלוי בהם.
3. **דגל `enrichmentCourses`.** מוצר C עצמאי ולא דורש את B, אך נדלק בדגל. אין להציג קורסים אלה בלי הדגל.
4. **מיתוג.** הקורסים הם Learni; רֶצֶף הוא פלטפורמת משרד העבודה. בשילוב — התוכן עובר לשפת העיצוב של רֶצֶף (`tokens.css`, קו הרצף), בלי מיתוג Learni/אורט בתוך המסך.
5. **פורמט מקור שונה.** שני הקורסים כתובים כ-HTML/מצגות/SPA — **לא** בסכימת `LESSON`. נדרש שלב המרה.

## 4. המלצה — Adapter, לא נגן שני

**לא לבנות** נגן קורס נפרד לכל מקור. הדרך היחידה שעומדת בכלל "תשתית אחת":

> **שכבת ייבוא (Course Adapter):** פונקציה שממירה תוכן קורס קיים → מערך `LESSONS` בסכימת המנוע, ואז אותו `enrichment-course.html` מנגן אותו. קלט אחד, מנוע אחד, ממשק תלמיד אחד.

- **פיננסקלאס = מועמד ראשון** (נקי ממינימיזציה, 8 נושאים מובנים, קהל יעד תואם). ההמרה: כל נושא → קורס, כל שיעור → `LESSON` עם `portions`+`questions`.
- **קורס AI = מועמד שני, חלקי.** מייבאים תוכן סטטי בלבד; המסלול ה"חי" נשאר מחוץ למנוע (קישור מודרך), עד תשתית AI מאושרת.
- **מה שנחסך מכפילות:** אין `CourseCard` שני, אין `SequenceLine` שני, אין מסך שיעור שני, אין מסד התקדמות שני. רק תוכן חדש בסכימה קיימת.

**גודל העבודה כשייפתח (הערכה גסה):** מיפוי סכימה + כתיבת adapter קטן = מסך אחד; המרת התוכן בפועל = עבודת תוכן (מיטל מנפיקה), לא הנדסה. עיקר המאמץ הוא **התאמת שפה ופירוק למנות** — לא קוד.
