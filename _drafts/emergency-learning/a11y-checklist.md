# רֶצֶף — צ'קליסט נגישות WCAG AA (W0-D9)

**גרסה:** 1.0 · **תאריך:** 15.7.2026 · **נלווה ל:** `a11y.css` + `a11y.js` + `design-system-brief.md §9`
**למי זה:** כל סוכן משימה שבונה מסך/רכיב. עבור/י על הצ'קליסט לפני שאתה מדווח "מוכן".
**בסיס:** WCAG 2.1 רמה AA. השכבה `a11y.css` נותנת חלק גדול "בחינם" — אבל aria, מבנה סמנטי וטקסט-חלופי הם עליך.

---

## 0. טעינה — 30 שניות (חובה בכל קובץ HTML)

```html
<html dir="rtl" lang="he">
<head>
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <link rel="stylesheet" href="tokens.css">
  <link rel="stylesheet" href="components.css">   <!-- אם משתמשים ברכיבים -->
  <link rel="stylesheet" href="a11y.css">          <!-- אחרון, מנצח -->
  <script src="a11y.js" defer></script>            <!-- עוזרי JS (אופציונלי) -->
</head>
<body>
  <a class="skip-link" href="#main">דלג לתוכן</a>
  <main id="main" tabindex="-1"> … </main>
</body>
```

> ❗ `viewport` **בלי** `maximum-scale` / `user-scalable=no` — חוסם זום (נכשל 1.4.4).

---

## 1. מבנה סמנטי וניווט מקלדת

- [ ] אלמנטים סמנטיים: `<header> <nav> <main> <button> <a>` — לא `<div onclick>`.
- [ ] `<main id="main" tabindex="-1">` קיים, ו-skip-link ראשון ב-`<body>`.
- [ ] סדר Tab הגיוני (עוקב אחר סדר ה-DOM ב-RTL). אין `tabindex` חיובי (>0).
- [ ] **כל** פעולה זמינה במקלדת: Tab/Shift+Tab לניווט, Enter/Space להפעלה, Esc לסגירה.
- [ ] אלמנט לחיץ שאינו `<button>/<a>` → `role` + `tabindex="0"` + מטפל ב-Enter **וגם** Space.
- [ ] אין "מלכודת מקלדת": אפשר לצאת מכל רכיב. ב-Modal/Drawer → כליאה מכוונת עם `rzA11y.trapFocus()`, ו-Esc משחרר.
- [ ] מיקוד גלוי בכל שלב (השכבה נותנת טבעת ברירת-מחדל — אל תסיר `outline` בלי חלופה).

## 2. יעד-מגע ומידות (מובייל)

- [ ] כל יעד מגע ≥ **44×44px** (`--tap`). לאייקון/קישור קטן → `.tap-target` על אב `position:relative`.
- [ ] מרווח בין יעדים סמוכים ≥ 8px.
- [ ] גוף טקסט ≥ **16px** במסכי תלמיד (`--text-body`). לא לרדת מ-14px בשום מקום.

## 3. צבע וניגודיות (AA)

- [ ] טקסט רגיל: יחס ניגודיות ≥ **4.5:1**. טקסט גדול (≥24px או ≥19px-מודגש): ≥ **3:1**.
- [ ] גבולות/אייקונים נושאי-מידע (UI components): ≥ **3:1** מול הרקע (1.4.11).
- [ ] **לא-רק-צבע (1.4.1):** כל סטטוס/מצב נושא סימן נוסף — נקודה + טקסט (`.chip`), אייקון-קו, או תווית. אסור "אדום=בעיה" בלי מילה/אייקון.
- [ ] קישור בתוך פסקה: קו-תחתון או סימן נוסף, לא רק צבע.
- [ ] בדיקת מצב forced-colors (Windows High Contrast): המסך עדיין קריא, מיקוד נראה, גבולות קיימים.

> **יחסים שנמדדו חי** (`accessibility.html`, מחושבים מהטוקנים): `--ink #173A4A` על רקע = 11.5:1 ✓ · `--ink-soft #607984` על לבן = 4.6:1 ✓ · `--brand-deep #08666D` על לבן = 6.7:1 ✓.
> ⚠️ **טורקיז המותג `--brand #0B8F98`:** על לבן = 3.9:1 → **טקסט גדול/מודגש בלבד** (לא גוף קטן). **לבן על `--brand` = 3.9:1** — עובר לטקסט גדול (≥18.66px מודגש / ≥24px) אך **לא** לגוף רגיל. לכן: תווית כפתור ראשי חייבת להיות ≥16px/700 או ≥18px, אחרת השתמש/י ב-`--brand-deep` כרקע. (ראה/י "פתוח למתכלל" בדוח W0-D9.)
> ⚠️ **טקסט צ'יפ-דופק** על רקע-ה-soft שלו: "נדרש קשר" = 3.4:1, "תשומת לב" = 4.1:1 — מתחת ל-4.5 לגוף קטן. הנקודה+הטקסט מספקים "לא-רק-צבע", אך אם הצ'יפ נושא מידע קריטי כטקסט קטן — כדאי להכהות את צבע-הטקסט (פתוח ל-W0-D5).

## 4. תמונות, אייקונים וגרפים (1.1.1)

- [ ] כל `<img>` תוכן → `alt` תיאורי. תמונה דקורטיבית → `alt=""`.
- [ ] אייקון-כפתור בלי טקסט גלוי → `aria-label` על הכפתור. אייקון דקורטיבי → `aria-hidden="true"`.
- [ ] **גרף/דיאגרמה:** `<svg role="img" aria-label="…">` **או** `<figure>`+`<figcaption class="chart-alt">` גלוי, **או** טבלת-נתונים `.sr-only`. הקו/הצבע לבד אינם מספיקים.
- [ ] מגמה מתוארת במילים ("עלייה מ-60% ל-75% השבוע"), לא רק ויזואלית.

## 5. טפסים

- [ ] לכל שדה `<label for>` (או `aria-label`). אין placeholder כתחליף ל-label.
- [ ] שדה חובה: `required` + `aria-required="true"` + סימן גלוי (`.req-mark` ★).
- [ ] שגיאה: `aria-invalid="true"` + הודעת-טקסט מקושרת ב-`aria-describedby` (לא רק מסגרת אדומה).
- [ ] קבוצות (radio/checkbox) בתוך `<fieldset>`+`<legend>`.

## 6. מצבים דינמיים וסטטוס מילולי (4.1.3)

- [ ] שינוי-סטטוס שלא בפוקוס (נשמר / נשלח / עודכן דופק) → שידור עם `rzA11y.announce('נשמר')` או `aria-live`.
- [ ] Toast → `aria-live="polite"` (כבר ב-`.toast-region`). התראה קריטית → `assertive`.
- [ ] `ProgressBar` → `role="progressbar"` + `aria-valuenow/min/max` + תווית-אחוז גלויה.
- [ ] מצב מערכת (שגרה/מרחוק/חירום) מתואר גם במילה, לא רק בצבע.
- [ ] Modal/Drawer: `role="dialog" aria-modal="true" aria-labelledby="…"`; פוקוס נכנס פנימה בפתיחה וחוזר לפותח בסגירה.

## 7. תנועה וזום

- [ ] `prefers-reduced-motion` מכובד (השכבה מכבה גלובלית; אל תכפה אנימציה הכרחית מעליה בלי סיבה).
- [ ] אין הבהוב > 3 פעמים/שנייה.
- [ ] זום 200% (דפדפן) — אין אובדן תוכן/פונקציה, אין גלילה אופקית מיותרת ב-320px.
- [ ] רוחב טקסט מוגבל ב-`ch` (לא גבהים קשיחים על מכלי-טקסט שגולשים בזום).

## 8. RTL ושפה

- [ ] `<html dir="rtl" lang="he">`. תוכן LTR נקודתי (מספרים/קוד) → `dir="ltr"` מקומי.
- [ ] מאפייני CSS לוגיים (`inset-inline`, `margin-inline`) — לא `left/right` קשיח. **בלי** `flex-direction: row-reverse`.
- [ ] אין טקסט חשוב כתמונה. שפה רגועה (בריף §1) — לא דרמטית, לא ילדותית.

---

## בדיקה מהירה לפני "מוכן" (5 דק')

1. **מקלדת בלבד:** נתק/י עכבר. עבור/י את כל המסך ב-Tab. כל פעולה נגישה? מיקוד תמיד נראה? Esc סוגר?
2. **זום 200%:** Ctrl/Cmd+ ×5. הכל קריא ושמיש, בלי גלילה אופקית.
3. **מובייל 320px:** יעדי מגע 44px, עמודה אחת, כפתור ראשי full-width.
4. **גווני-אפור:** דמיין/י בלי צבע — כל סטטוס עדיין מובן (טקסט/אייקון)?
5. **קורא-מסך (מדגמי):** כותרות בסדר היררכי, כפתורים בעלי שם, גרפים בעלי חלופה.

> חשד לכשל ניגודיות? בדוק/י ב-`accessibility.html` (מטריצת הטוקנים עם יחסים מחושבים).
> נכשל משהו? תקן/י לפני עדכון `status` ל-`done` ב-`tasks-data.js`.
